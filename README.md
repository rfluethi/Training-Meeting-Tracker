[![Plugin Check](https://github.com/rfluethi/Training-Meeting-Tracker/actions/workflows/plugin-check.yml/badge.svg)](https://github.com/rfluethi/Training-Meeting-Tracker/actions/workflows/plugin-check.yml)

WordPress plugin that displays the DACH training team's meetings on a WordPress page. The data source is a JSON file generated by a GitHub Action from the issues in the team repository.

## Features

- Shortcode `[training_meeting_tracker]` with attributes `show_upcoming`, `show_in_progress`, `show_past`, `years`, `heading_level`.
- Upcoming meetings: every issue without the `Erledigt` label whose date lies in the future (date, time, link to issue). Without such an issue the block says "No date set yet."
- Meetings in progress: every issue without the `Erledigt` label whose date already passed. This is the minutes pipeline.
- Past minutes: every issue with the `Erledigt` label, grouped by year.
- Date format on the frontend: `DD.MM.YYYY`.
- Settings page under Settings, Training Meeting Tracker, with the status of the last fetch.
- Transient cache with configurable duration, fallback to last good response on error, and a pause of ten minutes after a failed fetch. Only administrators see a notice that the data is not fresh.
- Full i18n (source strings in English). German translations included for `de_DE`, `de_DE_formal`, `de_CH`, `de_CH_informal` and `de_AT`.
- Cleans up its own data on uninstall.

## Quick start

1. Download the ZIP from the [Releases page](https://github.com/rfluethi/Training-Meeting-Tracker/releases) and install it under Plugins, Add New, Upload Plugin.
2. Activate the plugin.
3. Open Settings, Training Meeting Tracker, and verify the JSON URL. Default is `https://raw.githubusercontent.com/learn-wp-dach/learn-wp-dach-team/data/sitzungen.json`.
4. Place the shortcode `[training_meeting_tracker]` on a page.

Updates are installed the same way: download the new ZIP and upload it under Plugins, Add New, Upload Plugin. WordPress offers to replace the installed version. The plugin is not listed on wordpress.org, so WordPress does not announce new versions by itself.

## Shortcode

```text
[training_meeting_tracker]
[training_meeting_tracker show_upcoming="true" show_in_progress="true" show_past="true" years="3" heading_level="2"]
```

| Attribute          | Default | Values             | Meaning                                                            |
|--------------------|---------|--------------------|--------------------------------------------------------------------|
| `show_upcoming`    | `true`  | `true` or `false`  | Show the Upcoming meetings block.                                  |
| `show_in_progress` | `true`  | `true` or `false`  | Show the Meetings in progress block.                               |
| `show_past`        | `true`  | `true` or `false`  | Show the Past minutes block.                                       |
| `years`            | `all`   | `all` or integer   | Number of years shown in the past block (newest first).            |
| `heading_level`    | `2`     | `2` to `5`         | Heading level of the block headings. Year headings sit one below.  |
| `show_next`        | (none)  | `true` or `false`  | Legacy alias for `show_upcoming`.                                  |

Set `heading_level` so the block headings fit the outline of the page: `2` when the list sits directly below the page title, `3` when it sits below a heading of level 2.

## Requirements

- WordPress 6.7 or newer
- PHP 7.4 or newer

## Architecture

The plugin uses a slim two-component setup:

1. Team GitHub repository (`learn-wp-dach/learn-wp-dach-team`): a GitHub Action reads every issue with the `sitzung` label, parses the title date and the body fields (`Veranstaltung:`, `Uhrzeit:`) plus the `Erledigt` label, and writes a `sitzungen.json` file (schema v2, three lists) to the `data` branch.
2. This plugin: fetches the JSON via `wp_safe_remote_get`, validates the schema, caches the result as a transient, and renders the shortcode.

The plugin does not talk to the GitHub API directly. It only reads a static JSON file. This avoids token maintenance and rate limit concerns.

## External service and privacy

The plugin loads the JSON file from the configured URL, by default from `raw.githubusercontent.com`, a service of GitHub. This happens on the server, normally once per cache period, and never in the browser of a visitor. The request carries the address of the WordPress site in its user agent, as every request sent by WordPress does. No visitor data is transmitted. See the [GitHub terms of service](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service) and the [GitHub privacy statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement).

## Development

```bash
# Install dev dependencies
composer install

# Run the linter
composer lint

# Auto-fix where possible
composer lint-fix

# Run tests
php tests/run-tests.php

# Check that the version numbers agree
bash bin/check-version.sh

# Build the ZIP (the release workflow runs the same script)
bash bin/build-zip.sh               # version taken from the plugin header
bash bin/build-zip.sh 0.1.0-rc1     # version given explicitly
# Output: dist/training-meeting-tracker-<version>.zip
```

CI runs PHPCS (WordPress Coding Standards) and the tests on every push to `main` and on every pull request. Plugin Check runs on pull requests and before a release. Pushing a `v*` tag triggers the release workflow: it repeats all checks, builds the ZIP and attaches it to a GitHub release. Details in the release process section of [docs/Developer.md](docs/Developer.md). How to contribute: [CONTRIBUTING.md](CONTRIBUTING.md).
